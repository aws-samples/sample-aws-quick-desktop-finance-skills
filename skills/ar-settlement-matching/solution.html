收款核销 · 核心判据

以银行为锚，核销先准入、再守恒

判据规则结果
收款 ↔ 银行每张收款单都有银行到账；金额相等；日期不早于到账；到账未入账要列出不符
付款人归属付款账户属于这家客户挂错客户
核销准入收款和发票存在；发票未作废；同一客户；不重复核销无效核销
边界核销合计 ≤ 收款；核销合计 ≤ 发票应收超收款 / 超额
三方守恒Σ核销 = Σ发票已核销 = Σ收款已核销；收款 = 核销 + 未核销余额自检
应收闭环正常发票应收 − 有效核销 = 期末应收，对 1122；预收对 2203不符
无效核销不冲减应收：它被单独列出、写明原因，修正后再重跑，其余结果照常输出。

收款核销 · 判据边界

钱对上了，也不等于销对了票

盲区为什么抓不到处置可闭合性
收款挂错客户两户合计不变，内部对不出付款账户白名单 + 银行锚点，已在脚本中实现🟢 已闭合
坏数据中断整体一条错误让全部结果失效无效核销单列、其余照常，已在脚本中实现🟢 已闭合
同客户内销错票该销 A 票却销了 B 票，金额一样按客户付款备注、账龄先后规则复核🟢 可自补
第三方代付付款账户不在白名单，但确是合法代付取得客户委托付款书面确认🟡 需外部锚点
判据能证明“钱真到了、是这家客户付的、销的是它的票”，不能证明“销的正是客户想还的那一张”——这些边界已写入 Skill 的判据覆盖声明。
