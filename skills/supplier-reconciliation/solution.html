供应商对账 · 核心判据

先对余额，再对逐笔，最后闭合差额

判据规则结果
范围与期初有余额必须回函；双方期初相等未回函 / 不一致
余额恒等式双方各自：期初 + 发生额 = 期末不符
逐笔匹配供应商 + 归一化单号；同号多次 → 重复入账异常
单号纠错同金额、日期差 ≤ 3 天的两笔单边 → 疑似单号录错待核实
交叉一致金额相反 → 方向错误；不等 → 金额不符；类型不同异常 / 差异
在途识别截止日前 5 天内的单边项 → 在途，下期核销在途
差额闭合：供方期末 − 本方期末 = 期初差 + 供方独有 − 本方独有 + 配对金额差 + 供方自报余额差 − 本方余额表差，逐供应商成立。

供应商对账 · 判据边界

双方对上了，也不等于交易一定真实

盲区为什么抓不到处置可闭合性
在途被当错误截止日附近的正常未达账在途识别，已在脚本中实现🟢 已闭合
净额掩盖双向差异相互抵消逐家闭合 + 分向毛额，已在脚本中实现🟢 已闭合
对账单被篡改对账单经采购人员转交，可能被改由财务直接向供应商发函、回函直达🟡 需外部锚点
双方共同虚构我方与供应商串通，账面完全一致对接入库、物流与银行流水（#8 三单、#2 银行对账）🟡 需外部锚点
对账一致证明的是“双方记录相符”，不证明“交易真实发生”——这些边界已写入 Skill 的判据覆盖声明。

证据 JSON 同时输出为网页、PDF、Markdown、Excel 四种报告，差额归因表可直接发给供应商逐项确认。
