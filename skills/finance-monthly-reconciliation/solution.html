场景概述

🔴 传统月末结账的四大痛点

⏱️

耗时漫长

手动从 ERP 导出数据，Excel 逐行比对银行流水，反复核对差异。一轮完整对账需 3-5 个工作日。

❌

差错率高

人工比对容易遗漏、错行、误判。尤其是摘要不一致的交易，差错率高达 5-10%。

👥

人力浪费

出纳、会计、主管 2-3 人协作，反复沟通确认差异项，高学历财务人员做低价值重复劳动。

📊

报告滞后

对账完成后还需手工做 Word/PPT 报告，逐个发邮件给管理层。报告出炉时数据已失去时效性。

✅ 目标：Quick Desktop 将全流程压缩到 30 分钟以内

通过 AWS Quick Desktop 的连接器生态 + Python 沙箱 + 多格式文档生成能力， 构建一条从「外围系统数据采集」到「报告与分发草稿就绪」的流水线；分发由使用者确认后自行完成。 财务主管只需说一句 "开始本月对账"，即可一键触发全流程。

📥

数据采集 — 从 OneDrive / SharePoint 拉取 ERP 报表

财务人员将 ERP 导出的总账明细、银行对账单上传到 OneDrive 的固定目录。Quick Desktop 通过 OneDrive 连接器读取该目录中的文件。

操作示意：
• 调用 amazon_onedrive__ListChildren 扫描 /财务月末数据/202608/ 目录
• 调用 amazon_onedrive__GetItem 下载 Excel/CSV 文件到本地
• 自动识别文件类型（ERP 导出 vs 银行对账单 vs 应收应付）
涉及能力
☁️ OneDrive 连接器 📂 SharePoint 连接器 📁 本地文件系统
2
📧

邮件附件提取 — 从 Outlook 获取银行回单 PDF

银行每月末通过邮件发送回单。Quick Desktop 通过 Outlook 连接器搜索特定发件人的邮件，自动下载附件中的 PDF 并解析为结构化数据。

操作示意：
• 调用 email_search 搜索 subject:"银行回单" AND from:"bank@example.com"
• 下载 PDF 附件 → file_read_pdf 提取文本
• LLM 解析非结构化回单文本为标准化 JSON
涉及能力
📬 Outlook 连接器 📄 PDF 解析 🤖 LLM 文本理解
3
⚙️

数据清洗 + 自动对账 — 三维度智能匹配

在 Python 沙箱中加载多源数据，执行三维度自动对账：参考号精确匹配 → 日期+金额模糊匹配 → 摘要相似度匹配。自动标记匹配结果和差异项。

对账逻辑：
• Level 1：参考号精确匹配（PZ-xxxx ↔ BK-xxxx）
• Level 2：日期 ± 3天 + 金额 ± 1% 容差匹配
• Level 3：difflib.SequenceMatcher 摘要相似度 ≥ 0.6
• 输出：matched / erp_only / bank_only 三类清单
涉及能力
🐍 Python 沙箱 📊 pandas 🔍 difflib 模糊匹配 📁 run_python
4

智能分析 + 可视化 — 生成交互式仪表盘

仪表盘内容：
• KPI 卡片：对账匹配率 · 未匹配数 · 应收逾期 · 应付逾期 · 资金余额
• 银企对账结果饼图 · 账龄分布柱状图 · 资金走势折线图
• 部门费用分布 · 供应商 Top10 · 未匹配明细表

📈 ECharts 🎨 HTML 构建 🐍 Python 数据处理

🚀

生成分发草稿 — 由使用者确认后自行分发

对账完成后，在报告旁边生成报告邮件草稿和通知草稿，并告诉使用者草稿、Excel 和仪表盘的位置。本 Skill 不发送任何内容：它读取外部邮件和回单 PDF，所以不持有外发和建定时任务的工具。

草稿内容：
• 通知草稿：「月末财务对账完成，匹配率 80%（按银行流水计），60 笔未匹配待确认」
• 报告邮件草稿：对账概况 + 需要关注事项（HTML）
• 使用者核对后，用自己的邮件或聊天工具发送；收件人由使用者填写

固化为可复用 Skill

这套月末对账流程没有停在一次性脚本，而是写成了一个 Skill——一句"开始本月对账"随时复用。

🧭 模型编排（指挥官）

对话触发后，模型负责意图识别和工具编排：先判定数据模式，再决定调用哪些连接器、按什么顺序执行。模型不接触原始交易数据，只看结果摘要。

🔒 确定性对账（操作员）

对账引擎 reconciliation_engine.py 是确定性脚本：参考号精确匹配 → 日期金额容差匹配 → 摘要相似度匹配。同一份数据，每次结果相同。

📦 固化为 SKILL.md

finance-monthly-reconciliation

上层不折旧：目标、输入契约、7 步流程、输出契约、预警阈值、判据与盲区声明（核心资产）。下层可替换：连接器、脚本、路径随平台演进。

☁️ 云上模式（cloud）
数据源头在云端：OneDrive 取 ERP 数据包，Outlook 取银行回单，云端沙箱计算，生成完整报告与分发草稿，由使用者确认后自行分发。
💻 全部本地（local）
数据源头在本机/内网：授权文件夹取数，设备端计算，明细只写本地；分发草稿只含脱敏摘要，设备离线则停止、不降级。
一次构建，三种复用：① 对话框一句"开始本月对账"即时触发 ② 使用者自行配置定时任务，每月最后一个工作日 09:00 自动运行 ③ 对账结果与异常明细沉淀到 Agent Files，逐月形成可追溯的对账链。模式只看数据源头在哪：源头在云端就云上处理；源头在本地就走本地模式，原始文件留在本机，由本机脚本完成计算，只把结果摘要回传给云端模型。
