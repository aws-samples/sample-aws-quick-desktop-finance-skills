发票查验 · 核心判据

先把号码洗干净，再查五类唯一性

判据规则结果
号码归一化去空格、全角转半角、去数字段前导零后比对同号 / 变形 → 风险
跨期唯一与历史已报销发票池比对风险
组合指纹开票方税号 + 金额 + 开票日期相同、号码不同换号重开 → 风险
拆分报销同人、同开票方、同一天多张，每张低于上限、合计超上限风险
连号同人、同开票方 ≥ 3 张号码连续待核实
票面·日期·类别报销 ≤ 票面；不早于开票、不超 180 天；行业 × 类别；单笔上限风险 / 待核实
金额守恒：报销合计 = 通过 + 待核实 + 风险，一分不漏地分到三类里。

发票查验 · 判据边界

全部通过，也不等于每张发票都真实

盲区为什么抓不到处置可闭合性
号码变形绕过加空格、全角、前导零号码归一化，已在脚本中实现🟢 已闭合
跨期重复上季度报过，本季度再报历史发票池比对，已在脚本中实现🟢 已闭合
跨公司重复同一张票在集团内另一家公司报销汇总集团各公司发票池🟢 可自补
发票真伪 / 作废红冲号码唯一不代表发票真实有效对接税务发票查验平台🟡 需外部锚点
业务真实性票是真的，但消费与公务无关对接行程、审批单与消费明细🟡 需外部锚点
唯一性证明的是“没有被报第二次”，不证明“这张票是真的、这笔钱是公务”——这些边界已写入 Skill 的判据覆盖声明。
发票查验 · 过程可回溯

每个结论都能倒查回原始数据

① 逐笔留痕

植错版 272 笔各记原始号码、归一化号码、命中判据与关联单号。

② 输入指纹

报销、历史池、上限、类别规则、开票方五个输入各记 SHA-256 指纹。

③ 守恒 + 复算

报销 = 通过 + 待核实 + 风险；本机独立复算与云端一致。

证据 JSON 同时输出为网页、PDF、Markdown、Excel 四种报告，并按报销人汇总风险，审核可从任意一笔追溯到被重复的原单。
