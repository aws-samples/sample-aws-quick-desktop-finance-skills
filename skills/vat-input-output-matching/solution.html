增值税进销项 · 核心判据

算对税，还要判对能不能抵

判据规则结果
税额恒等式税额 = 金额 × 税率剔除
类别 × 税率税率合法，还要和商品服务类别对应：运输 9%、技术服务 6%剔除
唯一与状态发票号唯一；作废不计税；红字必须对应存在的蓝字剔除 / 不计税
销项所属期开票日期在本月；销方是本公司剔除
进项能否抵扣抬头是本公司；本月勾选；发票正常；不是餐饮、集体福利剔除 / 不抵扣
应纳税额销项 − (可抵扣进项 − 进项转出) − 上期留抵计算
守恒：全部销项税额 = 计入 + 作废 + 剔除；全部进项税额 = 可抵扣 + 不抵扣 + 剔除。每一分税额都有去向。

增值税进销项 · 判据边界

票面都对了，也不等于税一定交对

盲区为什么抓不到处置可闭合性
类别用错税率税率合法，但与业务不符类别×税率交叉白名单，已在脚本中实现🟢 已闭合
不得抵扣已抵扣餐饮、福利拿了专票就抵不得抵扣清单，已在脚本中实现🟢 已闭合
用途事后改变购进时用于生产，后来用于福利按领用记录计算进项转出🟢 可自补
发票真伪与异常凭证票面合规，但被税局列为异常对接税务发票查验与异常凭证清单🟡 需外部锚点
销售未开票有收入却没开票，销项漏计与收入明细、出库记录核对🟡 需外部锚点
判据能证明“已开的票算对了、该抵的才抵”，不能证明“该开的票都开了、票是真的”——这些边界已写入 Skill 的判据覆盖声明。
增值税进销项 · 过程可回溯

每个结论都能倒查回原始数据

① 逐票留痕

216 张发票各记计税状态（计入/可抵扣/不抵扣/作废/剔除）与原因。

② 期间与指纹

所属期、本公司税号、上期留抵固定；五个输入各记 SHA-256 指纹。

③ 守恒 + 复算

销项、进项、张数守恒成立；本机用同一份 CSV 独立复算，与云端一致。

证据 JSON 同时输出为网页、PDF、Markdown、Excel 四种报告，申报表上的每一个税额都能追溯到具体发票。
