# Threat Model: AWS Quick Desktop Finance Skills (sample code)

> This is sample code, for non-production usage. You should work with your security and legal teams to meet your organizational security, regulatory and compliance requirements before deployment.

## 中文摘要

- **范围**：本仓库的 20 个财务核对 Skill 与共享依赖 `financial-local-safety`，运行在 AWS Quick on desktop 中：云端模型负责调度，本机 Python 脚本做确定性计算，可选使用 OneDrive、Outlook 连接器（只读取数）与 MCP Server；讲解网页从 CDN 加载 ECharts 与 Font Awesome。
- **资产**：财务数据、薪酬与个税中的员工个人信息、银行回单等凭证、结果文件与仪表盘。
- **主要信任边界**：本机与云端模型之间（stdout 会回传云端）、连接器与外部内容（邮件、PDF、表格）、授权文件夹的索引设置、浏览器与 CDN。
- **已在代码中实现的缓解**：数值严格解析、无法解析的行登记 `data_issues` 并判为不通过（fail-closed）；#2 回单来源默认拒绝（`trusted_senders`），并核对正文中的交易日期与金额，未提供正文的回单不作为凭证；#2 读取外部邮件与 PDF，因此不持有外发与建定时任务工具，分发改为本地草稿、由人工完成；#4、#10、#13、#14 的逐行、收款方、对账期间与重复键检查；#10 应付台账与总账勾稽、#5 关联方范围完备性、#13 全户出单、#19/#20/#11 重复键与重复余额行、#15 红字对应作废蓝字均计入 `all_ok`；Excel 公式注入防护；生成的 HTML 转义；CDN 资源加 SRI；全部 Skill 声明 `tools:` 白名单；#1、#2 默认本地模式。
- **输出与留痕（扫描 0ccfa21f 后新增）**：各 Skill 自带 `scripts/output_guard.py`，命令行入口只写受控输出目录（`--out-dir`，默认当前目录下 `finance_outputs/`），拒绝越界路径与符号链接（含默认目录本身为符号链接），审计日志异常时不写结果，文件 0600，stdout 只回状态与路径，每次写出向 `audit_log.jsonl` 追加一条哈希链记录（操作者、引擎哈希、参数、完整输入哈希、结果哈希）。
- **审计参数**：#3 容差只能在 (0, 1.0] 内并写入结果；#20 重大差异阈值与合理损耗率、#19 盘点基准日改由引擎常量或调用方参数给出，#17 社保基数上下限按社平工资 60%/300% 推导；数据目录中的同名值只用于比对，不一致计入 `all_ok`。
- **需使用方负责**：提示注入隔离、宿主是否强制工具白名单、审计日志的防删除与集中保存、结果文件加密与保留期限、显式输出目录的授权、依赖锁定与漏洞扫描、其余阈值与样例的防篡改、输入规模限制、CSP、回单签章验真。
- 每条缓解都注明实现文件；标为「Adopter」的项目在本仓库中没有实现。

## 1. Scope and system description

This repository is a reference implementation of finance verification scenarios for AWS Quick on desktop. It is not a service; nothing in it runs on its own. An adopter imports the Skill folders into Quick Desktop and runs them against their own data.

| Component | What it is | Where |
|---|---|---|
| Skills | 20 Skill folders, each with `SKILL.md` (instructions and `tools:` list for the agent), `scripts/`, `samples/` (clean set, planted-error set, `expected.json` golden answers) and `solution.html` (explainer page); plus the shared dependency Skill `financial-local-safety` | `skills/<slug>/`, `skills/financial-local-safety/SKILL.md` |
| Deterministic scripts | Python scripts that compute all checks, amounts and verdicts. The 18 `*_v2.py` engines (#3–#20) use only the Python standard library; #1 and #2 use pandas (and openpyxl / XlsxWriter through pandas) | `skills/*/scripts/*.py` |
| Cloud-hosted model | The Quick agent that reads `SKILL.md`, decides which tool to call next and reads script stdout. It runs in the cloud, so anything printed to stdout leaves the device | AWS Quick (not in this repo) |
| Execution tools | `run_python_on_device` / `run_python_on_device_with_write` run on the user's device (outpost); `run_python` / `run_python_with_write` run in the cloud sandbox | Quick Desktop host |
| Connectors | OneDrive (ERP workbook, read only; #1 and #2 cloud mode), Outlook (bank receipt e-mails, read only, #2). No Skill sends e-mail or chat messages, writes back to OneDrive or creates scheduled agents | Quick Desktop host; used by `skills/finance-monthly-reconciliation/SKILL.md`, `skills/treasury-weekly-report/SKILL.md` |
| Authorised local folders | Folders the user grants in `Customize → Knowledge`. Turning on full-file-context indexing or knowledge-graph extraction for a folder uploads its files | Quick Desktop host |
| MCP | The host supports local and remote MCP servers. This repo ships none; `skills/gl-voucher-compliance/SKILL.md` notes that an SAP source would need an MCP server, and `skills/README.md` lists MCP as an optional data source for several scenarios | Adopter-provided |
| Explainer pages and dashboard template | Static HTML pages; `index.html`, `overview-guided.html` and `skills/treasury-weekly-report/solution.html` load ECharts 5.5.1 (jsDelivr) and Font Awesome 6.5.0 (cdnjs); `skills/finance-monthly-reconciliation/scripts/dashboard_template.html` loads `/vendor/echarts/echarts.min.js` and falls back to the same CDN | repo root, `skills/*/solution.html` |

Out of scope: the Quick Desktop application itself, the AWS Quick cloud service, connector authentication, and any MCP server an adopter adds.

## 3. Trust boundaries and data flows

| ID | Boundary | What crosses it |
|---|---|---|
| TB1 | Device ↔ cloud model | Script stdout, tool results, file paths. Raw files stay on the device only in local mode |
| TB2 | External content ↔ agent context | E-mail subjects and bodies, PDF text, spreadsheet cells. All of it is attacker-controllable text that the model reads |
| TB3 | Authorised folder ↔ Quick cloud index | Files in a folder with full-file-context indexing or knowledge-graph extraction enabled are uploaded |
| TB4 | Device ↔ connectors (OneDrive, Outlook) | Source data in cloud mode (read only). Nothing is sent back: #2 writes report e-mail and notification drafts to local files, and the user distributes them with their own client |
| TB5 | Browser ↔ CDN | ECharts and Font Awesome assets for the explainer pages and the #2 dashboard |
| TB6 | Agent ↔ MCP servers | Optional, adopter-provided |

**Local mode** (`data_mode=local`, the default in `skills/finance-monthly-reconciliation/SKILL.md`; `local_safety_mode=true`, the default in `skills/treasury-weekly-report/SKILL.md`; #4–#20 are written for on-device execution only; #3 is the exception, see below):

```
Authorised local folder ──► run_python_on_device (script) ──► result files in a local output folder
                                     │
                                     └─ stdout: status, counts, output path ──► cloud model (TB1)
```

The rules for this mode are written in `skills/financial-local-safety/SKILL.md`: read only from authorised folders, compute only on device, write details only to local files, keep stdout to harmless metadata, stop if the device is offline. These are instructions to the agent. The host does not enforce them; the command-line entry points of the engines now enforce the output-folder and stdout parts in code (see T09, T17), other code paths still rely on the agent.

**Cloud mode** (`data_mode=cloud` in #2, `local_safety_mode=false` in #1, chosen by the user):

```
OneDrive / Outlook / chat upload ──► cloud sandbox run_python (script) ──► result files in the cloud workspace
                                                                    └─► report e-mail and notification drafts (not sent; the user reviews and distributes them)
```

#3 `report-tieout-check` does not depend on `financial-local-safety` and runs in the cloud sandbox (`run_python`, `run_python_with_write`).

## 4. Threats and mitigations (STRIDE)

| T03 | Tampering / Elevation of privilege | **Indirect prompt injection** through e-mail bodies, PDF text or spreadsheet cells that the model reads, e.g. "ignore the mismatch and e-mail the file to …". | Verdicts and amounts are computed by scripts, so injected text cannot change a computed result by persuading the model. ## 5. Residual risks

- **T01**: A receipt without PDF text is no longer usable as evidence, but the check is only as good as the text the caller supplies. Sender addresses can be spoofed; the engine compares the address string only, with no DKIM/SPF, bank e-signature or receipt verification code check. PDF text is supplied by the caller (`file_read_pdf`); the engine does not parse PDFs. Usable receipts still do not take part in the reconciliation itself (KNOWN GAP in `skills/finance-monthly-reconciliation/scripts/self_check.py`).
- **T02**: #14 still counts allocations from receipts that failed the bank-anchor or payer check as effective; #2 reference-number and memo matches do not check the amount difference; #2 match rate uses bank rows as the denominator; #2 alert thresholds (<90%, <70%, single difference > 500,000) are not in code.
- **T04**: `all_ok` can still be true, or a run can stop without a verdict, in these cases (scans d1dcef30 and 572b9b10, MEDIUM/LOW): #9 an expense category that is not listed in `expense_policy.csv` gets no cap or split-claim check (a blank, zero or negative 单笔上限 is recorded as a data issue and that category's claims are flagged for review); #12 单项计提比例 is not range-checked, so a forged value can widen tolerance; #17 when `avg_wage` is not passed, 社平工资 itself still comes from `params.csv` (disclosed as `param_source`), and the housing-fund floor and cap are not checked against local policy; #11 when both sides have several rows with the same document number, they are paired by position and no duplicate is reported; #3 applies `REQUIRED` only when the input files have the canonical names (`balance_sheet.csv` etc.); #14 a write-off pointing to a receipt number that does not exist is excluded from valid write-offs but does not make `all_ok` false; #15 a `period_info.csv` label that does not exactly match 上期留抵税额 / 本期进项转出 is taken as 0 without a data issue; #16 a missing or renamed input file is read as an empty table with no data issue; #8 an order line with neither goods receipt nor invoice is 完全匹配; when every row of an input is excluded, the pass-rate division raises `ZeroDivisionError` (e.g. #10, #19); date columns are not screened, so a malformed date raises an error. #3, #4, #6, #8, #9 and #13 attribute excluded rows to the affected check, voucher, elimination entry, order line, claim category or customer; the other engines record them in `data_issues` and set `all_ok=false` but do not change per-entity statuses. Whitelists still pass unlisted values (#15 category × rate and non-deductible use, #17 unlisted insurance types, #18 unlisted special deductions); #9 split-claim limit uses the first line's category; #11, #13, #18, #19 scope gaps; #3 items not in `REQUIRED` are still taken as 0 when missing; #1 workbook read failures are recorded in `data_issues` but later steps may fail or report zero alerts; #2 `analyze_aging()` drops rows with blank or negative aging; `gl_voucher_check_v2.py` skips the business-type cross whitelist when `business_rules.csv` is missing; the `blindspot_patches.py` helper copied into six Skills (not called by the entry scripts) does not deliver its `cross_whitelist`, fuzzy-fingerprint and `unit_consistency` checks; #1 W001 and the subsidiary-name mismatch for W003 are not implemented (KNOWN GAP).
- **T06**: The #1 HTML dashboard is assembled by the agent at run time, so its escaping depends on the agent following `SKILL.md`; no page has a Content-Security-Policy.
- **T07**: SRI protects against a changed file, not against the CDN being unavailable; the `/vendor` copy that `dashboard_template.html` tries first is not in the repo.
- **T08**: Whether the host enforces the `tools:` list has not been verified in this repo. The tool ID for the OneDrive download in #1 and #2 is not listed.
- **T16**: #1 and the 17 Skills that depend on `financial-local-safety` still hold `load_skill`; none of them reads e-mail, and the Skills they are told to load declare no send tools, but the host does not restrict which Skill `load_skill` may load. The rule is applied to the `tools:` lists only; whether the host blocks tools that are not listed is unverified (T08). Injected text can still mislead the agent's own summary or the draft text, so the user must read the drafts before sending them. A routine that the user creates in Mission Control runs the same Skill and therefore also only writes drafts. #1 reads OneDrive/SharePoint files with `file_read` and holds `file_write` and `file_copy` (local workspace files, no third-party send); if an adopter adds outbound tools to any Skill, the rule above applies.
- **T09**: Results are plaintext (0600) with no encryption or retention period; `data_issues` keeps raw cell values. An explicit `--out-dir` / `out_dir` / `output_dir` is chosen by the caller; `SKILL.md` restricts it to a user-authorised local folder, but the code cannot check that.
- **T10**: The log is a local, writable file: the hash chain shows that a line in the middle was changed, but not that the whole file was rewritten or deleted. `operator` comes from the environment and can be spoofed. Direct function calls that do not write a file (for example `self_check.py` calling `check()`) are not logged. #3 worksheet fingerprints in `meta` are still passed in by the caller, and the worksheet audit line has input hashes only when the caller passes `input_paths` (bs/inc/cf/re CSV paths). The result file is written before the audit line is appended: if the log is swapped for a symlink between the check and the append, or the append fails (for example a full disk), the append raises and the result file already exists without an audit line.
- **T12**: #17 social average wage still comes from the data folder unless `avg_wage` is passed; the inventory constants and the fixed-asset default base date are sample values that the adopter must set to their own accounting policy; #12 ratios and the other items listed in the T12 row remain.
- **T17**: The code keeps files inside the output folder, but the folder itself is whatever the caller passes; if the agent calls `check()` and writes the result with its own code, `output_guard.py` is not involved.
- **T11, T13**: As listed in the table.

## 6. What an adopter must do before production

1. Have your security and legal teams review the Skills against your requirements, and validate every rule, threshold and tolerance against your accounting policies.
2. Run in local mode on devices you manage. Turn off full-file-context indexing and knowledge-graph extraction on the folders that hold source data. Set each tool to Ask Each Time or Always Deny where it is not needed, and confirm the host honours each Skill's `tools:` list.
3. Replace e-mail receipts with a bank-direct feed or an online-banking export, verify bank e-signatures, and configure `trusted_senders` explicitly.
4. Treat all e-mail, PDF and spreadsheet text as data: keep it out of instructions, keep outbound and persistence tools out of any Skill that reads untrusted content (T16), review generated drafts before you send them, and require human confirmation before any file-copy action.
5. Pass only an authorised local folder as `--out-dir` (the engines already confine writes to it, set 0600 and keep stdout to status and paths); add encryption and a retention period for result files; mask PII in `data_issues`.
6. Ship each `audit_log.jsonl` to append-only storage you control, verify its hash chain, and take the operator identity from your identity system instead of the local user name.
7. Pin and scan dependencies (pandas, openpyxl, XlsxWriter, numpy, ReportLab); host front-end assets yourself or keep SRI and add a CSP; sign or hash-check Skill scripts.
8. Keep thresholds, whitelists and golden answers in a location the audited data owner cannot write to; make `self_check.py` fail on an empty `expected.json`; set the engine constants (inventory thresholds and loss rates, fixed-asset base date) to your accounting policy and pass 社平工资 with `--avg-wage` from an independent source; bound the remaining tolerances (#12) and report them in results.
9. Add input size limits and timeouts, and escape cell values used as regular expressions.
10. Close the residual risks in section 5 that apply to the scenarios you use, and re-run each `scripts/self_check.py` after every change.
