01 · What it is

Quick Desktop 是什么

它是 Amazon Quick 的原生桌面应用，把 Quick 的能力延伸到你的机器上 —— 对你的文件、已连接的服务，以及工作之间的上下文关系，拥有直接且持续的访问能力。

📁

不再是"上传文件"

授权哪些文件夹由你决定，Quick 可以直接读、写、搜索和索引，无需上传；对某个文件夹开启 Allow full file context 或 Always remember file information 时，才会上传该文件夹的文件。

🔗

跨服务合并信息

连上邮件、日历、聊天、CRM 后，可以在一次对话里从多个服务取数、执行动作并交叉比对，不用来回切工具。

🧠

越用越懂你的上下文

逐步构建关于人、项目、决策的知识图谱，并把偏好与工作方式留在长期记忆里，回答因此带上你的工作背景。

💡
已正式发布（GA）。Amazon Quick on desktop 已于 2026 年 9 月在 macOS 与 Windows 上正式发布。对话、记忆与知识图谱保存在你的 Amazon Quick 账户中，Web、移动端与桌面端通用。套餐与价格见官方定价页，可用区域见官方区域页。
02 · Capabilities

能力底座

场景方案能不能跑通，取决于下面这些能力是否可用、权限是否够。这里按落地时的关注点重新组织，官方文档的原始编排见用户指南目录。

📁

本地文件访问

在 Customize → Knowledge 按文件夹授权。添加文件夹只授予访问；全文检索索引与知识图谱抽取按文件夹分别打开，访问级别可设 Full Access / Read Only / Ask Each Time。

🔌

连接器与 MCP

内置 Slack、Outlook、Teams、Gmail、Google Calendar、OneDrive 等云连接器；MCP Server 支持 Local、Remote、从配置文件 Import 三种接法。

🧰

系统工具与权限

在 Customize → Connectors 逐项启停。每个工具可设 Always Allow / Ask Each Time / Always Deny，还能按单个读写操作细化 —— 比如整体放开但对某个写操作要求逐次确认。

⚡

Skills

按需加载的指令集。系统技能（带 System 徽标）覆盖文档、演示文稿、表格、网页浏览、代码执行、知识图谱、转写等，可开关、不可编辑；自建技能在 Customize → Skills 管理，草稿经 Try it 测试后 Publish 生效。

⏱️

定时任务与 Mission Control

把工作挂到定时任务（routine）上，在 Mission Control 统一看运行状态、待办输入、KPI 与历史产出，并可暂停或立即执行。定时任务在云端运行；读本机文件、浏览器自动化、本地代码执行这类步骤需要电脑开机且应用在线。

🤝

委派编码 Agent

通过 ACP 协议把开发类任务派给 Kiro 或 Claude Code，Quick 汇总结果回报，适合"分析在 Quick、改代码在 IDE"的分工。

🕸️

知识图谱与记忆

自动抽取人、客户、项目、事件、行动项等实体及关系，保存在你的 Amazon Quick 账户中（按用户隔离）。在 My context 查看与管理；连接应用的自动抽取与文件夹抽取（Customize → Knowledge）分别开关。

🎚️

响应模式

对话与定时任务都可选 Fast / Balanced / Smart。按任务复杂度在速度与质量之间取舍。

内置系统工具

在 Customize → Connectors 的连接器表中逐项启停，并通过 Manage permissions 配权限。

工具能做什么要留意的地方
🔍 Web Search联网检索并返回带引用的摘要，可抓取指定网页全文可在单次对话里临时开关

🌐 Browser Automation启动浏览器导航、与页面元素交互、填表、截图、提取文本默认使用独立的浏览器实例和你的配置文件副本；在 Settings → General 开启 Use my existing browser 则使用你自己的浏览器（需开启远程调试，不用时建议关闭）

🐍 Code Execution在沙箱中编写并运行 Python，用于数据分析、计算、文件处理与图表生成使用预装包；同一对话内变量保留；文件访问遵循文件夹授权，另可访问系统临时目录
✍️ Engram Builder分析你的写作风格并存成 engram，之后用你的语气产出内容适合起草邮件、消息与文档

📊 Working with your data用自然语言查询通过 Quick spaces 连接的数据集与仪表盘可见范围取决于组织的权限设置

Always Allow

该工具读写全开，操作不逐次征询确认（默认）。

Ask Each Time

每次操作前都要你确认，适合写操作与敏感数据。

Always Deny

完全禁止 Quick 通过该工具执行任何操作。

03 · Interface

界面速览

左侧边栏做导航，顶栏切换浮层面板，中间是主内容区。知道东西在哪，配置和排查都会快很多。

位置内容
侧边栏 · 主导航Chat（发起和继续对话，最主要的工作入口）、Feed（按优先级排列的动态、日历与待办，来自已连接的服务）、Library（集中浏览、搜索和复用内容与 Quick 资源）、Customize（代理、技能、连接器、知识与品牌素材）、Apps（打开和构建交互式应用）、Spaces（团队维护的精选集合，可直接对其对话）、More（Research、Data、Dashboards、Automations 等）；用 Edit navigation 选择和调整导航栏显示的条目

CustomizeAgents（代理）、Skills（技能）、Connectors（Web/云连接器、MCP Server、编码 Agent、系统工具）、Knowledge（本地文件夹授权与索引）、Brand assets（Word/PPT 模板）；知识图谱与记忆在 My context 中管理
顶栏面板Feed（信息流浮层）、Mission Control（后台任务与代理活动）、All data and apps（已连接数据源状态）
Home随时段变化的问候语、聊天输入区（选择 Agent / 响应模式 Fast、Balanced、Smart / 思考强度 Off–High / 无痕 Incognito 对话）、未连接数据源的设置卡片、Quick Briefs（最高优先级 Feed 条目的摘要）

04 · Skills

Skills 机制

Skill 是把一套工作方法固化下来的载体 —— 这也是 Playbook 里所有场景方案的交付形式。理解它的结构，才能把自己的业务流程沉淀成可复用资产。

📋

Instructions

一份 SKILL.md：多步工作流、每步的校验标准、失败时的降级路径。比提示词模板重得多。

🔧

Tools

技能可声明要带的工具。技能激活时，这些工具自动载入当前会话。

📎

Reference files

执行期可访问的脚本、模板、配置等支撑文件。

三种创建方式

在 Customize → Skills → Create 下：

From chat —— 描述你要什么，Quick 起草指令、挑工具、写出 SKILL.md，你再审阅修改。

From file / From folder —— 导入 .md 或 .zip，或选择根目录含 SKILL.md 的文件夹（连同脚本等参考文件）。

顺手沉淀 —— 多步任务完成后，Quick 可能主动提议把这个流程存成技能。

三种调用方式

点名 —— 在对话里提技能名，例如"用网页浏览技能看下这一页"。

自动识别 —— Quick 判断请求与某技能相关就自动加载，比如你要做 PPT 时演示文稿技能会自己上。

Try it —— 在技能详情面板点 Try it，直接开一个已载入该技能的会话，常用于发布前测试。

💡
写技能的关键取舍：把确定性计算（指标、匹配、图表）下沉到脚本，只把判断类工作（字段映射确认、建议生成、异常升级）留给模型。这样产出的数字可复现、可审计，同时保留 AI 的解释能力。本 Playbook 的场景方案都按这个原则组织。
