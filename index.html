  • 连接已有系统 → 无需开发
  • 业务人员自建自动化流程
  • 实战发现真实场景 → 反哺平台规划
  • 两条路不矛盾，Quick 是平台建好前的"快速通道"
"先用起来，再系统化"——Quick 帮您今天就产出 AI 价值，同时为未来的平台建设积累真实的业务场景和数据。

六层能力模型

通用 AI 聊天工具停留在第 1-2 层——Quick 构建了完整的六层闭环

1对话 + 生成  智能问答、文档分析、数据处理所有 AI 工具都行
2连接 + 执行  对接邮件、IM、云存储、浏览器操作行业趋同
3知识积累  持续从日常工作中构建个人知识图谱Quick 优势
4流程固化  Skill：将跨系统工作流标准化为一键可复用的自动化流程Quick 特色
5自主运行  定时任务（routine）：按计划自动执行，无需人工触发Quick 特色
6本地安全  本机文件按文件夹授权访问，工具权限逐项可控Quick 亮点
Quick 的核心价值 = 让您的工作流"长出记忆和肌肉"。越用越懂您，做过一次不用教第二遍，人不在它也在工作。

Skill：从"做一次"到"自动跑"

不是展示"AI 能做什么"——而是展示如何将 AI 能力固化为可复用、可自动运行的标准化流程

阶段数据输入处理输出差异化
L1 单次对话处理 手动上传文件 AI 对话分析 生成报告 任何 AI 工具都能做
L2 Skill 固化 指定文件 / 目录 标准化流程 一句话 → 标准输出 做过一次不再教，任何人都能用
L3 跨系统编排 连接器 → ERP / 业务系统 / OA 多源合并 + 异常检测 报告 + 自动上传 + 邮件发送 Skill + 连接器 = 端到端自动化
L4 全自动运行 定时自动触发 自动执行全流程 人不用动，结果自动到位 定时任务（routine）+ 本地安全闭环

L3 端到端工作流示意：以财务周报为例

怎么落地

从装客户端到跑通第一个场景的四步，以及把技能装进 Quick Desktop 的具体操作。

1

装客户端

macOS 需 13 (Ventura) 或更高，仅支持 Apple Silicon（M 系列），不支持 Intel Mac；Windows 需 Windows 10 64 位（1903 或更高）。均需 8GB 内存，安装需 2GB，建议再留 10GB 以上给索引与知识图谱。安装包见官方下载页，套餐与价格见官方定价页。

2

登录与连数据

组织账户输入 AWS Quick 账户名后点 Sign In，在浏览器中完成登录；组织配置了专用身份提供商时选 Continue with single sign-on (SSO)。随后按引导连邮件、日历、IM，并授权技能要读写的本地文件夹。

3

配权限、试技能

按最小必要原则设工具权限（写操作先用 Ask Each Time），再导入一个依赖少的技能，用样例数据跑通全流程。

4

沉淀与自动化

把稳定下来的流程存成技能，挂上定时任务，在 Mission Control 里观察运行质量并迭代。

① 导入

Customize → Skills → Create → From folder，选择技能文件夹（如 skills/ap-aging/），SKILL.md 与 scripts/ 等参考文件一起导入；单个 .md 或 .zip 用 From file。先点 Try it 测试，再 Publish。

② 配齐依赖

在 Customize → Connectors 连接技能声明的连接器，并确认所需系统工具已启用；在 Customize → Knowledge 添加技能要读写的文件夹。财务技能还需一并导入共享依赖 financial-local-safety。

③ 三种调用方式

对话里点名技能、让 Quick 按描述自动识别，或在技能详情面板点 Try it 开一个已载入该技能的会话。

定时任务在云端运行。到点即触发，应用关闭或电脑关机也照常执行；但读本机文件、浏览器自动化、本地代码执行这类步骤，要求电脑开机、应用运行并保持连接，否则该步骤不可用。本库财务技能读本地文件、跑本地脚本，挂定时任务时请保证电脑在线。

企业接入

企业版用户用 Quick Web 端已在使用的登录方式登录桌面端：默认不需要在 IdP 注册 OIDC 应用、不需要 Client ID 或 extension access，管理员一次性添加桌面连接器即可。登录时浏览器需已有 Quick Web 会话；一次登录最长 30 天。

AWS Quick 桌面端企业部署指引（官方）

桌面连接器、专用身份提供商（OIDC + PKCE）与 MDM 策略的官方配置文档
1

确认前提

Enterprise 版、home Region 支持 agentic 功能（见官方区域页）、管理员权限、桌面端 1.1.4053 及以上。

2

（可选）分批放开

添加连接器会立即对全员开放；要分批，先在 custom permissions 中限制 Quick desktop 能力。

3

添加桌面连接器

控制台头像 → Manage account → Inbound connectors → Quick Desktop → Add desktop connector，选 Use Quick's existing configured sign-in method。

4

验证并分发

连接器卡片显示 Quick Desktop / Enabled 后，再向用户分发客户端。

支持的身份提供商

默认的桌面连接器沿用 Quick 已配置的登录方式，IAM Identity Center、IAM Federation、Quick 原生用户均可。需要在 IdP 中单独管理桌面登录时，可改用专用身份提供商配置（advanced，OIDC + PKCE）：官方为 Microsoft Entra ID、Google Workspace、Okta、Ping Identity 提供了分步文档，其他兼容 OIDC 的 IdP 未提供官方分步文档。已用 desktop extension 配置的组织，原配置继续可用。

强制走企业 SSO

用 MDM 下发 DisableSocialLogin 策略，隐藏社交登录入口并在服务端拦截，使企业 SSO 成为唯一登录路径。

# macOS 偏好域
com.aws.QuickWork.mac → DisableSocialLogin = true

# Windows 注册表
HKLM\SOFTWARE\Policies\Amazon\Quick
  DisableSocialLogin (REG_DWORD) = 1
IdP 中的邮箱地址必须与 AWS Quick 里该用户的邮箱精确匹配，否则映射失败。受限网络下还需把 Quick 与 IdP 域名加入允许列表。应用会自动沿用操作系统的代理配置，无需单独设置。
